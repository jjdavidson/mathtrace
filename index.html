Why MathTrace

              
Mathematics is a network of ideas

              
MathTrace treats a paper as a navigable mathematical environment rather than only a linear document. The ordinary exposition remains available, but the web interface makes the structure, evidence, provenance, and reusable ideas surrounding it easier to explore.


              

                

                  
Web-native exposition

                  
Wikilinks let readers move directly between dependent ideas without repeatedly searching through sections. Interactive examples, simulations, and 2D or 3D animations can expose a construction dynamically and allow readers to change parameters instead of relying on a single static figure.

                

                

                  
Explicit mathematical structure

                  
MathTrace draws inspiration from Lean, where definitions and proofs have explicit dependencies and can be formally checked, and from Connected Papers, where research literature—including work on arXiv—is explored through a graph. A dependency graph makes a large project easier to organize and gives a new collaborator a visible route through the required ideas.

                

                

                  
Collaboration with local authorship

                  
Node-sized contributions support collaborations on the scale of Polymath projects without erasing individual authorship. Each definition, example, lemma, computation, or proof can record its contributors while remaining connected to the shared argument.

                

                

                  
Granular provenance and verification

                  
AI assistance can be disclosed exactly where it occurred rather than applied as one label to an entire paper. Lean-verified nodes can likewise be identified inside the surrounding informal argument, making both formal verification and unresolved gaps easier to understand in context.

                

                

                  
Parallel refereeing

                  
A dependency graph makes technical review divisible. Experts can referee the nodes closest to their specialties while seeing the precise prerequisites and downstream uses, so no single referee must verify every component. Editorial synthesis remains necessary, but the mathematical checking can be distributed and parallelized.

                

                

                  
AI-readable papers and a mathematical canon

                  
Fully AI-generated papers should be presented in a structure that humans can audit node by node instead of as an opaque block of prose. Across many papers, reuse and downstream dependence also reveal which ideas are genuinely pivotal. A lemma that becomes infrastructure for numerous arguments can acquire theorem-level visibility, producing a natural canonization of mathematics from the structure of its use.

                

              

            


            

              
Getting started

              
Open or author a MathTrace paper

              
    
                
  1. Select Add paper in the global header.
    2. 
                
  2. Choose a native MathTrace folder containing mathtrace.paper.md and its node files.
    3. 
                
  3. Select a paper node to read its paper-level content, then double-click it to open its internal dependency graph.
    4. 
              

              
A MathTrace paper consists of one required mathtrace.paper.md file, a nodes/ directory of Markdown nodes, and an optional demos/ directory for interactive content. The manifest identifies the work; MathTrace supplies node discovery and graph-layout defaults. Every loaded paper is a flat, self-contained module.

              
Design goal. The graph is a distilled model of the paper's mathematical structure—not a table of contents or a paragraph-by-paragraph transcript.

            


            

              
Native project structure

              
Select the project folder itself when opening a native paper. MathTrace recursively finds every .md file beneath nodes/.

              
example-paper/
├── mathtrace.paper.md
├── nodes/
│   ├── graph/
│   │   ├── chromatic-number.md
│   │   └── homomorphism.md
│   └── main-theorem.md
└── demos/
    ├── graph-coloring.js
    └── graph-coloring.css

              

                
mathtrace.paper.mdRequired minimal manifest. Supplies the paper ID, title, authors, and paper-wide prose.

                
nodes/**/*.mdOne conceptual mathematical unit per file. Subfolders are editorial organization and are independent of node IDs.

                
demos/**/*Optional scripts, stylesheets, and assets referenced by interactive node content. The complete directory is preserved on download.

              

              
Node IDs are stable mathematical identities; paths are organizational locations. Moving a file between folders must not change its ID, and changing an ID does not move its file. Dependencies always use IDs rather than paths.

            


            

              
File reference

              
Writing node Markdown files

              
Each node file begins with YAML frontmatter enclosed by --- lines. Everything after the second delimiter is rendered as the node's Markdown content. The reader displays the stable node ID beneath the title so it can be copied into new requires lists and wikilinks.


              
Required frontmatter

              

                

                  
AttributeTypeUse

                  
                    
idNonempty stringUnique stable identifier. Prefer a paper-qualified descriptive ID such as matrix-method.heuberger-matrix. Do not encode the node's current folder path in the ID.

                    
titleNonempty stringThe node's only display name, shown in the graph and at the top of the content panel.

                    
kindNonempty stringClassifies the idea. Store lowercase values such as definition, lemma, proposition, theorem, corollary, construction, example, algorithm, computation, exposition, remark, conjecture, or question.

                    
requiresList of node IDsCreates incoming dependency arrows from direct prerequisites. It must always be present, even as []. IDs must exist, be unique in the list, and keep the graph acyclic.

                  
                

              


              
Default graph colors

              
The graph uses restrained, light fills for six common mathematical roles: definitions are blue, lemmas green, propositions teal, corollaries lavender, theorems rose, and examples amber. All other node kinds are white. Selection and dependency highlighting temporarily override these defaults.


              
Optional frontmatter

              

                

                  
AttributeTypeUse

                  
                    
statusStringEditorial state such as draft, reviewed, final, or deprecated.

                    
tagsList of stringsSubject labels for filtering and compact display.

                    
sourceMappingRecords provenance such as source filename, section, page, theorem number, DOI, arXiv ID, or LaTeX label.

                    
citationsListBibliographic keys or structured citations directly supporting the node.

                    
aliasesList of stringsAlternative names for future search and link resolution.

                    
relatedList of node IDsUseful non-prerequisite connections. These do not create dependency arrows.

                    
contributorsListPeople who authored, reviewed, translated, or substantially revised the node.

                    
ai_assistanceMappingRecords the level of AI assistance, model, and whether a human reviewed it.

                    
lean_verifiedMappingLinks a Lean declaration and optionally its repository and commit. Omit it when no verification is known.

                    
superseded_byNode IDNames the replacement for a deprecated node.

                  
                

              


              
Treat node IDs as durable references. A paper-qualified ID such as matrix-method.heuberger-matrix stays fixed when the file is reorganized. A node is native when its ID begins with the current paper ID followed by a dot. To use a node from another paper, copy that node and all of its required prerequisites into the consuming paper without changing their IDs. MathTrace draws these imported nodes with dashed borders.

              
Metadata presentation. Kind, status, subject tags, AI assistance, and Lean verification are intended to appear as compact badges. Longer provenance belongs in a metadata detail view.

Content conventions

              
    
                
  • Put one coherent idea in each file: a definition, a complete example, a construction, or a result together with its proof.
    • 
                
  • Begin the prose directly after the frontmatter. Do not add a Main Content heading; the interface already displays title.
    • 
                
  • Use $...$ for inline mathematics and \[...\] or $$...$$ for display mathematics.
    • 
                
  • Write [[example-paper.chromatic-number]] to display another node's title, or [[example-paper.chromatic-number|chromatic number]] to supply a custom label.
    • 
              


              
Complete node example

              
---
id: example-paper.homomorphism-chromatic-number
title: Homomorphisms and chromatic number
kind: lemma
requires:
  - example-paper.graph-homomorphism
  - example-paper.chromatic-number
status: reviewed
tags:
  - graph theory
source:
  section: graph-homomorphisms
  label: lem:hom-bound
ai_assistance:
  level: copyediting
  human_reviewed: true
---

If there is a graph homomorphism from $X$ to $Y$, then
\[\chi(X) \leq \chi(Y).\]

This uses [[example-paper.graph-homomorphism]] and
[[example-paper.chromatic-number|the chromatic number]].

## Proof

Pull a proper coloring of $Y$ back through the homomorphism.

            


            

              
Interactive documents

              
Inline HTML and JavaScript demonstrations

              
Node bodies support ordinary Markdown together with raw HTML. A node may contain controls, Canvas, SVG, tables, or any other browser element. Inline scripts execute when the node is rendered, and scripts or stylesheets beneath demos/ can be referenced with paper-root-relative paths.

              
<div id="coloring-demo">
  <label>Vertices <input type="range" min="3" max="30" value="8"></label>
  <canvas width="720" height="420"></canvas>
</div>

<link rel="stylesheet" href="demos/graph-coloring.css">
<script src="demos/graph-coloring.js"></script>

              
The script runs after the node HTML has entered the document, so it can select and modify the node's elements directly. Paper-local scripts do not receive a MathTrace context object. Do not wrap them in a DOMContentLoaded listener because the main page has already loaded.

              
For browser modules, add type="module" to the entry-point script and use relative imports to files vendored beneath demos/. For example, import * as THREE from "./vendor/three.module.min.js";. Bare package imports are not resolved. Relative module paths are rebuilt from the locally opened paper, so the demonstration remains self-contained and works offline. Retain license and version notices for vendored dependencies.

              
Short demonstrations may use inline <style> and <script> elements. Larger demonstrations should keep JavaScript and CSS under demos/ so the mathematical prose remains readable. Scope CSS selectors and element IDs to the demonstration to avoid collisions with the interface or another open node.

              
Trusted documents. HTML and JavaScript execute with the same browser access as the viewer. MathTrace reads papers locally and does not upload them, but users should open executable papers only from sources they trust.

            


            

              
File reference

              
Writing mathtrace.paper.md

              
This required top-level file represents the paper as a whole. Its body is displayed whenever the paper node is selected; the manifest itself is not an ordinary mathematical node and has no node-level dependencies. Keep its frontmatter minimal. MathTrace always reads nodes from nodes/ and supplies its own layout defaults.


              
Required frontmatter

              

                

                  
AttributeTypeUse

                  
                    
idPaper slugStable identity and node namespace. Use lowercase letters, digits, and single hyphens; do not use dots.

                    
titleNonempty stringFull display title used on the paper node and overview.

                    
authorsNonempty listEach item is a name or a mapping with name and an optional complete HTTPS arxiv URL.

                  
                

              


              
If an author mapping supplies arxiv, clicking that author's name in the paper overview opens the linked arXiv page in a new tab. Publication dates, status, keywords, affiliations, and source links belong in the Markdown body when they are useful to readers.


              
Complete minimal example

              
---
id: example-paper
title: "An Example MathTrace Paper"
authors:
  - name: Ada Example
    arxiv: "https://arxiv.org/search/math?query=Example,+A&searchtype=author"
  - Emmy Example
---

## Abstract

This paper studies a family of graph colorings.

## Introduction

The main result is [[example-paper.main-theorem]].

## Conclusion

We conclude with several open questions.


              
Using nodes from another paper

              
Copy only the referenced node and the transitive prerequisites needed to keep its requires graph complete. Retain every original node ID. If an ID does not begin with example-paper., the node is imported and receives a dashed border. When its source paper is also loaded and contains that exact node ID natively, MathTrace connects the two paper nodes. This snapshot model keeps the consuming paper independently loadable without bringing in the source paper's entire graph.

            


            

              
Structural authorship

              
Choose idea-sized nodes

              
A good node is the smallest chunk that still expresses a complete mathematical idea. The purpose of the dependency graph is to separate and distill the paper's structure, not to maximize the number of nodes.

              
    
                
  • Keep a theorem, lemma, proposition, or corollary with its proof unless the proof contains a genuinely reusable intermediate result.
    • 
                
  • Keep several definitions together when the paper introduces them as one inseparable piece of setup.
    • 
                
  • Let exposition span several paragraphs when those paragraphs form one narrative structure.
    • 
                
  • Do not split mechanically at paragraphs, sections, list items, or LaTeX environment boundaries.
    • 
                
  • Move title, abstract, introduction, conclusion, acknowledgments, and broad motivation to mathtrace.paper.md. Short transitions need not become nodes.
    • 
              

              
Use the rendered graph as an editorial test. Its major routes should correspond to the conceptual stages of the paper. If it is noisy, look first for fragments that only make sense together. If a hidden intermediate result is independently reusable, give it its own node.

              
Matrix Methods. Its revised trace uses broader idea-sized nodes and separates applications into their own ID path. Use the rendered graph—not paragraph count—as the test for useful granularity.

            


            

              
Existing papers

              
Convert LaTeX into native MathTrace files

              
An AI-assisted conversion should read the complete source paper and produce an ordinary MathTrace folder containing mathtrace.paper.md and node Markdown.

              
Conversion sequence

              
    
                
  1. Read the entire paper before deciding where nodes begin and end.
    2. 
                
  2. Extract paper-level metadata and prose into mathtrace.paper.md.
    3. 
                
  3. Draft coherent mathematical units; combine each result with its proof and merge inseparable setup.
    4. 
                
  4. Assign stable paper-qualified IDs, descriptive titles, lowercase kinds, and an explicit requires list to every node.
    5. 
                
  5. Infer direct prerequisites from definitions, notation, constructions, citations, labels, references, and proof use—not only explicit \ref commands.
    6. 
                
  6. Render the graph and revise the segmentation until it communicates the paper's architecture.
    7. 
                
  7. Compare every node with the original source and record human review.
    8. 
              

              
Fidelity rules

              
    
                
  • Preserve the original claims, formulas, hypotheses, prose meaning, and proof logic.
    • 
                
  • Do not silently repair, strengthen, weaken, or complete an argument.
    • 
                
  • Do not invent citations, verification, bibliographic data, or mathematical dependencies.
    • 
                
  • Record source locations and surface uncertainty for human review.
    • 
                
  • Use structured ai_assistance metadata for material AI work.
    • 
              

            


            

              
Creating and editing nodes

              
Open a paper, select an ordinary graph node, and choose Edit node in the content-panel header. The complete Markdown file—including its YAML frontmatter—opens as source in the left panel. Create node appears only while a paper is open and always targets that paper.

              

                
Markdown-only edit
Saving a body-only change rerenders the selected content without laying out the graph again.

                
Frontmatter edit
Changing id, kind, title, requires, or other frontmatter validates and redraws the graph while preserving its view state.

                
Create node
New files are placed beneath nodes/newly-added/. Their stable IDs remain independent of that temporary organizational location.

                
Delete node
A confirmation dialog lists every direct dependent. Delete anyway removes the deleted ID from dependent requires lists and replaces matching wikilinks with [[deleted reference]].

                
Validate
Save is rejected without changing the project if frontmatter is invalid, an ID or path conflicts, a prerequisite is missing, or dependencies form a cycle.

              

              
The source editor highlights mathematics delimited by $...$, $$...$$, \(...\), or \[...\] in green. Highlighting is visual only and never changes the Markdown source.

              
Renaming a node automatically migrates its dependency references, internal [[node.id]] links, and paper-overview links while retaining the node file's existing path.

              
Save validates and applies the source, Delete previews the dependency impact before removal, and Cancel discards the draft immediately. Escape asks before discarding unsaved source. Ctrl/Command+S also validates and saves. Changes remain in browser memory until the paper is downloaded from the Papers menu.

            


            

              
Paper dependencies and focused paper view

              
Each loaded MathTrace folder becomes one node in the paper dependency graph. If paper A contains an imported node whose exact ID is native to loaded paper B, MathTrace draws an edge from B to A. Loading another paper rebuilds and fits this graph, so newly resolved relationships appear immediately without loading either paper's complete node graph into the workspace.

              
Closing an unchanged paper restores the paper dependency graph's previous pan and zoom. If creating, editing, or deleting a node changes a cross-paper dependency, that saved camera is invalidated and the rebuilt paper graph is fitted so the new relationship is visible.

              

                
Select paper
Select a paper node once to display its mathtrace.paper.md overview in the right panel.

                
Open paper
Double-click a paper node to replace the paper dependency graph with that paper's internal node graph, fitted to the panel. Pressing Enter on a focused paper node is the keyboard equivalent.

                
Delete paper
Choose the red × in a paper node's top-right corner. MathTrace reports whether the loaded paper has edits and asks for confirmation before removing it from the workspace.

                
Create node
The action is available only in the focused paper view and creates a node in the currently open paper.

                
Close paper
Choose Close paper beside Create node to return to the rebuilt paper dependency graph at its previous pan and zoom.

              

              
The Papers menu lists every paper by ID and marks it Edited or Unedited. Use its Download button to save a ZIP containing mathtrace.paper.md, nodes/, and the optional demos/ directory. Existing node paths are preserved; files created in the browser remain beneath nodes/newly-added/. Use Add paper to load another folder.

            


            

              
Using the viewer

              
Paper workspace and focused paper

              
The workspace displays one fitted graph of loaded papers and their resolved cross-paper dependencies. Opening a paper temporarily replaces that graph with the paper's fitted internal dependency graph. MathTrace does not place internal graphs in movable paper windows.

              

                
Select
Click a paper or mathematical node to read it and highlight its direct prerequisites and dependents.

                
Pan
Drag empty graph space to move the current graph.

                
Zoom
Use a wheel or trackpad gesture. Zoom is centered at the pointer.

                
Fit
Adjust zoom and position so the complete current graph fits inside the panel. Paper graphs are fitted automatically after loading or closing a paper; internal graphs are fitted when opened.

                
Paper overview
Select a paper node to display its paper-level Markdown.

                
Expand panel
Let the selected node cover both panels for large figures and interactive demonstrations. Choose Shrink panel to restore the split view.

                
Hide content
Reveal the graph area behind the right panel without changing the graph transform.

              

            


            

              
Validation and local-file privacy

              
Before drawing a native paper, MathTrace verifies paper metadata, node frontmatter types, unique node IDs, existing dependencies, and an acyclic node dependency graph.

              
The viewer reads selected MathTrace folders inside the browser. The interface does not upload paper files. Node edits remain in browser memory until you explicitly download them. Because node HTML and JavaScript are executable, only open papers from sources you trust.
